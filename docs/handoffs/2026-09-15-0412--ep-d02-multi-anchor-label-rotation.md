## Binary frontier

Because `V^I_{multi,S,v}` is already nonempty, only two prevalence topologies
remain:

- **A, recommended — selective prevalence:**
  `V^I_{multi,S,v}` is a nonempty proper subset of `R_{multi,v}`. At least one
  multi-anchor exact key rotates and at least one distinct multi-anchor key is
  wholly label-stable. This preserves stable advanced references beside
  selected Soul-sensitive composition puzzles. C3c.43-A means a stable exact
  `I_v` map is not Soul-inert: every operative realization still needs a
  material Soul-responsive predicate witness. The cost is another taxonomy and
  a token risk where one obscure showcase key carries all rotation.
- **B — universal prevalence:** `V^I_{multi,S,v}=R_{multi,v}`. Every multi-
  anchor exact key has some Soul pair with different equal-count singleton sets.
  This gives the cleanest class rule and prevents one showcase key from carrying
  the direction. The cost is a universal authoring and validation obligation,
  no stable multi-anchor reference, and compulsory coupled-only slack in every
  multi-anchor row. It does not mean every Soul or every Soul pair differs.

A has a tight minimum of three exact keys: one variable multi-anchor, one stable
multi-anchor, and one stable one-anchor key. With two supported Souls that gives
at least six pair rows. A complete example is:

- variable multi Ashen: common
  `C={H/action,H/build,S/build,X/action,X/build}`; Firebound
  `I={H/action,S/build,X/build}`; Stonebound
  `I={H/build,X/action,X/build}`;
- stable multi Dreamglass: common `C=I={S/action,S/build}`;
- stable one-anchor Iron: common `C={H/action,X/action}` and
  `I={H/action}`.

The singleton union is all six labels. Stable Dreamglass supplies an exact-two
multi-anchor fiber, demonstrating that A leaves the inherited exact-two class
open. Variable Ashen and one-anchor Iron retain coupled-only edges.

B adds no exact-key minimum beyond the two nonempty classes. It forces every
multi key to degree at least three, so every exact-degree-two realization lies
in the stable one-anchor class. Each row in that inherited fiber has one fixed
singleton edge, one coupled-only edge whose supporting package is the complete
width-two footprint, and four absent cell edges. Under B every exact pair row
in the complete domain has at least one coupled-only cell, but no global
package-width cap follows.

Proof for A needs one completely classified variable multi key, one distinct
stable multi key with exact-set equality across every supported Soul, and the
inherited stability proof for every one-anchor key. Proof for B needs a valid
unequal-set witness for every multi-anchor key. A variable cell requires a
positive singleton-package witness under one Soul and complete exclusion under
another; failed search is unresolved.

The recommendation is A. Review split on it: formal/frontier review favored B's
clean universal class grammar, while gameplay review favored A's curated
contrast. A was retained as the recommendation because exact `b` includes fine
instance/state/boundary snapshots and C3c.43-A already guarantees material
Soul response beneath stable label maps; forcing every such snapshot to invent
a label swap risks formulaic compliance rather than fun. B remains fully
defensible if universal predictability is preferred.

Neither direction selects a numeric quota inside A, every-Soul or every-pair
variation inside B, witnessing Souls, exact labels, overlap or exchange
severity, definition/instance/state/boundary ownership, predicates, packages,
contexts, receipts, routes, disclosure, ease, power, live rebinding,
acquisition, persistence, release, or implementation. Soul-pair coverage and
overlap follow prevalence one choice at a time.
