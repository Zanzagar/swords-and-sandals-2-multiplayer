## Selected direction

Retain

`V^I_{multi,S,v}=R_{multi,v}`.

Every fixed multi-anchor exact Relic realization has at least one supported-
Soul pair with different singleton-backed cell-label sets. C3c.59-A keeps the
singleton count equal, C3c.57-A keeps the total cell palette fixed, and C3c.61-
A keeps every one-anchor exact key's sole label stable. The owner chose the
universal rule because Soul-dependent reconfiguration fits **Souls and
Simulacra** better as a systemic identity than as a selected-subtype exception.

Every multi-anchor exact key therefore has `d_v(b)>=k_v(b)+1>=3` and at least
one coupled-only cell in every Soul row. No exact-degree-two key can be multi-
anchor, so C3c.55-B's entire exact-two fiber is one-anchor. Each row in that
fiber has one stable singleton label, one coupled-only edge, and four absent
cell edges. Every exact pair row in the complete domain now has at least one
coupled-only cell. No global package-width cap follows.

C62-B does not require every supported-Soul pair to differ on a key, the same

quality, power, or live Soul rebinding. A token implementation could copy one
obscure exchange for one niche pair across the catalog; later choices must

## Ternary frontier

For a fixed multi-anchor exact key `b`, define

`D_v(b)={{s_1,s_2} in binom(S_v,2) : I_v(b,s_1) != I_v(b,s_2)}`

and

`R_{pair,v}={b in R_{multi,v} : D_v(b)=binom(S_v,2)}`.

C62-B makes every `D_v(b)` nonempty. It also already derives that every Soul
has some differently mapped counterpart on every multi-anchor key; a separate
“every Soul participates” card would be fake. C3c.63 instead classifies the
meaningful pair-edge topology:

- **A — no pair-complete keys:** `R_{pair,v}` is empty. Every multi-anchor key
  has both an unequal Soul pair and an equal Soul pair.
- **B, recommended — mixed pair completeness:** `R_{pair,v}` is nonempty and
  proper. At least one key distinguishes every Soul pair, while another
  preserves an equal-pair affinity.
- **C — universal pair completeness:** `R_{pair,v}=R_{multi,v}`. Every two
  supported Souls have different equal-count singleton maps on every multi-
  anchor key.

B lets some Relics operate as sharp Soul-identity prisms and others expose
affinities or echoes. That honors the title's thematic pull without forcing
every small Relic footprint to encode an expanding Soul roster. Its cost is a
real resolution-depth taxonomy, at least two multi-anchor keys, and at least
three supported Souls. A can repeat one global Soul grouping everywhere. C has
the cleanest rule but imposes the universal bound
`|S_v|<=binom(d_v(b),k_v(b))` on every multi-anchor key: the six-cell system
allows at most twenty unique equal-count sets, and a degree-three/count-two key
allows only three Souls.

With Firebound `F`, Stonebound `S`, and Veilbound `V`, a non-pair-complete
Ashen can use `I_F=I_V={H/action,S/build}` and
`I_S={H/build,X/action}`. A pair-complete Dreamglass with
`C={S/action,S/build,X/action}` can use
`I_F={S/action,X/action}`, `I_S={S/build,X/action}`, and
`I_V={S/action,S/build}`. B requires both structures; it does not select these
labels. Stable one-anchor Iron remains outside this card.

If the supported roster contains exactly two Souls, C62-B already makes the
single pair differ on every multi-anchor key, so C is derived. A or B therefore
forces `|S_v|>=3`. Pair completeness still says nothing about exact label
overlap: two unequal equal-size sets may exchange one member or be disjoint.
Overlap is the next dependent atom after C63.

Proof of a pair-complete key needs exact `I_v` inequality for every unordered
Soul pair. Proof of a non-pair-complete key needs one proven unequal pair and
one proven equal pair; equality needs complete singleton-package exclusion,
not merely matching positive witnesses. C3c.43-A still requires material
predicate response when two Souls share the same `I_v` projection.
