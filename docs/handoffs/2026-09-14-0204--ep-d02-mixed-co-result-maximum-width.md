## Sole active choice

For fixed ruleset/catalog version `v`, one combatant's sole active Soul Relic
root, legal positive context `h`, and reachable final-input state `y` at that
context's one boundary, let `c(h,y)=|a_h(y)|`. Counts never sum across
combatants, roots, contexts, or times. Define

`W_v = sup {c(h,y)}`

in the nonnegative integers extended by infinity. C3c.45-C proves `W_v>=2`.
Finite `W_v` is attained by some legal reachable state because receipt counts
are integer-valued. `W_v=infinity` means every finite width is met or exceeded
somewhere in the legal reachable versioned domain; no one state must contain
infinitely many receipts. Dormant capacity does not raise `W_v`.

- **A, recommended — exact maximum two:** `W_v=2`. The inherited co-result
  witness makes a real dual weave, while no state can emit a third receipt.
  This keeps one Relic root legible and bounds later UI, resolver, payoff, and
  validation surfaces. It excludes a genuine triple constellation, and even a
  pair can still become a premium double-dip.
- **B — exact maximum three:** `W_v=3`. At least one real triple receipt state
  exists and none has four. This can create a memorable coordinated team
  constellation, but the third result risks filler, format-specific design
  pressure, and a larger burst/coverage premium.
- **C — maximum four or more:** `W_v` is finite and at least four or is
  infinity. A reachable four-plus state is mandatory; technical permission is
  insufficient. This permits elaborate engine builds but makes receipt count a
  major power and complexity axis. If selected, a dependent choice separates
  finite from reachable-unbounded width and then fixes an exact finite value
  where applicable.
